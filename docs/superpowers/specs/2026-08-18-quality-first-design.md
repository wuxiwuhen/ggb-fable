## 1. 方向决策理由

1. **证据强度排序**：成功率数字与提升曲线 > 架构叙事。面试 30 秒扫描时
   「30 用例成功率 85%、迭代后从 60% 提升」是硬通货。
2. **infra 不产生质量**：服务端 loop / 多任务 / 网关没有一条让画出来的图更好。
3. **demo 缺口小**：canvas-xml 与会话持久化已有，刷新后现场可恢复（当次生成中断重发
   即可），不构成 demo 塌方。
4. **部署知识已到位**：归档文档覆盖三层分离、$0/$7/$25 取舍阶梯、休眠机制、JVM/无头
   否决记录、8 项并发竞态——「知道有哪些方式方法（含付费的）」这个目标已达成。

## 3. eval 细节（沿用改进计划 §3，此处只记增量）

- 用例分层（基础构造 5 / 函数图像 5 / 动态可拖动 5 / 多步组合 8 / 陷阱与预算边界 7）、
  断言类型、每条 3 次取多数、温度入报告——**均按改进计划 §3 原设计执行**。
- 增量①（任务 2）：**裸 LLM 基线**——同 30 用例单次调用，系统提示词附 GGB 命令文档
  摘要，无工具循环 / 无预算控制 / 无自愈 / 无视觉验收；断言同一套。对比表输出四列：
  成功率 / 命令报错率 / 幻觉命令数 / 平均往返轮次。目的：把 agent 流程的价值变成数字。
- 增量②（任务 4）：本地 LiteLLM 供多模型对比（deepseek vs glm 至少两档），选型结论写
  进报告；不部署到任何云。

## 4. 迭代循环纪律（任务 3 的方法论）

1. 每轮：跑 eval → 失败归因分类 → 只修最高频类别 → 复测 → 报告版本 +1
2. prompt 修改走已有版本化设施（prompts/v1 v2 + prompt-version API），版本号进报告
3. INCIDENTS.md 纪律沿用：幻觉命令、rootCause 兜底失败、视觉误判改坏图等案例当场记
4. 停止条件：连续一轮无显著提升（<3pp）即收官，转任务 5
